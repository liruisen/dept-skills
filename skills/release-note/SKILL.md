# 发版说明（提测明细 + 发版简报）

一次运行产出两段，**详版在前、简版在后**：

- **详版明细**：给测试同事——回答"要怎么覆盖、哪些实现层行为用例不会写、什么现象属正常不是 bug"
- **简约发版说明**：给审批/留档——回答"这次发版用户能看到什么变了"，不是"这次开发改了什么代码"

用户只要其一（如只要发版说明）时只出那段。

## 工作流

1. 确定版本范围：用 git log 找上一个版本号 bump 提交
   （`git log --oneline -S '"version": "x.y.z"' -- package.json`），
   列出 `上个bump..HEAD` 区间的提交。
2. **素材不只看 commit message**：详版的机制条目要从迭代过程挖——方案文档、review 结论、
   拍板口径、代码里的防御逻辑/降级路径，git log 里没有这些。没把握的机制宁可不写。
3. 两段都写，详版在前；产出后带一句可调整的口子（要更细/更粗说一声），不追问。

## 详版明细写法（交测试）

两部分结构，逐项连续编号，**同一行为只出现一次**：

- **一、PRD/用例已覆盖的简列**：一行一项，开头注明"按用例回归即可"。用例里写过的
  不展开——这部分是索引，帮测试确认范围完整，不是复述用例。
- **二、代码机制标注（用例/PRD 未写，测试时注意）**：实现层行为，测试不看代码就不知道、
  容易误报 bug 或漏测的。典型素材：
  - 隐藏功能与参数（如 URL 开关、隐藏列）
  - 降级与兜底行为（断网回退、匹配不到显示什么）
  - 时序与延迟（"恢复后数秒才消失属正常"，防误报）
  - 口径约定（蜂鸣几响、文案定稿、某列为什么是 `-`）
  - 防御机制（防重、防误匹配、幂等）
  - 全站生效的横切改动（不只本次功能模块）
  - "设计内不是漏做"的缺失说明（如只读无删除）
  - 依赖后端/环境的条件（"后端 X 上线前显示 -"）

条目用业务可测语言，说清**什么时候会看到、为什么**；标题可加粗便于扫读。
末尾视迭代内容附测试操作提示（如断网模拟的正确姿势），有才写。

## 简约发版说明写法（审批/留档）

- 只要变更内容，不带风险、测试验证、回滚板块
- 按业务模块归组（如：发票 / 门卡 / 权限 / 其他），每项一行
- 业务语言，只写用户可感知的变更；用户可感知的数字保留（如"上限放宽至 5MB"）
- 过滤掉：
  - 技术实现细节（"画布拖拽""图层管理""分页断点""CDN 压缩"这类词不出现）
  - 内部提交：重构、构建配置、docs、test
  - debug 级小修（宽度调 2px、气泡加宽之类）——并入"其他：若干界面与体验修复"
- 标题带产品名和版本号，正文总共 5 行左右

## 风格

短句、克制。不用"显著提升""全新""彻底解决"这类词；"加载提速""体验修复"这类平实说法即可。

## 示例

输入：2.9.2 约 80 个提交（发票模板编辑器、PDF 模板渲染、多页分页、图片压缩、5MB 上限、解密卡、权限位、侧栏记忆、气泡宽度等）。

详版骨架（交测试）：

> **一、PRD / 测试用例已覆盖，按用例回归即可**
>
> 1. 模板编辑器：画布操作、块属性编辑、iPad/窄屏适配
> 2. PDF 输出与多页分页：页脚、续页留白、页码
> …（一行一项，不复述用例）
>
> **二、代码机制标注（用例未写，测试时注意）**
>
> 8. **图片双链路重试**：加载失败自动重试 2 次，最坏 ~31s 才显示裂图——慢 ≠ 挂了
> 9. **PDF 同图双请求**：网络面板会看到同 URL 两次（缓存合并，实际传输一遍），属正常
> 10. **侧栏展开记忆按员工存**：换浏览器/清存储后回默认收起，不是 bug
> …

简版示例（审批/留档）：

❌ 开发内容罗列（被否的写法）：

- 表头骑跨页界时整块断到下页，不再切半行
- 窄屏抽屉开关改图标+文字胶囊，选中块时属性钮高亮
- 岗位列表表格高度少减 2px，全分辨率恒出纵向滚动条

✅ 发版说明（通过的写法）：

> **TTHotel Pro 2.9.2 发版说明**
>
> 1. 发票支持自定义模板：新增模板编辑器（适配 iPad/窄屏），PDF 与打印按模板输出，支持多页发票自动分页与页码
> 2. 发票图片优化：上传上限放宽至 5MB，加载提速，失败自动重试
> 3. 门卡新增「解密卡」功能（恢复空白卡），支持批量操作
> 4. 权限：新增「修改房价」权限，无权限时订单房价仅可查看；岗位权限新增发票独立权限位
> 5. 其他：若干界面与体验修复
